# 领域文档

## 探索前阅读

- 阅读根目录 `GLOSSARY.md`；若存在 `GLOSSARY-MAP.md`，则按映射阅读相关上下文。
- 阅读 `docs/adr/` 中与当前工作相关的决策记录。
- 缺少这些文件时继续工作，不因缺失要求提前补齐；由 domain-modeling 在术语或决策明确时按需创建。

## 布局

本仓库采用单一上下文：

- `GLOSSARY.md`：领域词汇表。
- `docs/adr/`：系统级架构决策记录。

`GLOSSARY.md` 只记录项目特有的业务概念，每个定义控制在一两句话；不存放技术实现或功能清单。术语有容易混淆的同义词时，明确推荐用词与应避免的叫法。

ADR 使用递增编号，如 `0002-<主题>.md`。仅在决策难以逆转、未来读者需要背景解释且确有替代方案与权衡时新增；记录背景、选择及理由。

## 术语与决策

- 输出、issue 标题与测试名称中的领域术语遵循 `GLOSSARY.md`。
- 新术语尚未进入词汇表时，先判断是否确有领域概念缺口，再补充。
- 发现实现与 ADR 冲突时，明确指出冲突及重新讨论的理由。
