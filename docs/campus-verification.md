# 校园账号核验服务

本模块提供“校园账号已验证”结论，不证明学生类别、实名、当前在读、学校背书或操作者本人。学校通信只使用 `@hehuoda/sicau-connectors/auth` 构建入口，不抓取学籍、成绩或课表。

## 小程序交互

微信小程序个人中心的账号菜单提供“校园账号核验与学校资料”，页面为 `pages/campus/index`，与唯一导航注册表中的 `campus-verification` 对应。页面分别显示当前资格及北京时间截止、本人只读学校资料、本次事务状态；同学期重验不会延长到下一学期，普通失败不撤销原有效资格。到期前七天提醒下一学期重新核验，到期仅影响发布招募、申请、接受邀请和查看联系方式。现有队伍与招募演示仍保留演示边界，核验不启用正式业务。

页面先读取平台告知全文与版本，独立同意后才创建事务；版本变更后重新同意。验证码只能使用平台返回的有界内嵌位图，失败时禁止提交不可见图片的答案。刷新清空旧答案，提交保留密码原值并立即清空页面密码、验证码；这些输入只驻留页面，不进入 Pinia、存储、URL 或日志。

应用切后台立即清密、取消页面请求并停止轮询；恢复仅查询原事务，不恢复旧挑战或重放密码。离页、卸页尽力取消事务；退出或账号代次变化同步清除私人页面，后端通过会话撤销及事务期限收敛。请求结果不明先查原事务，处理中每两秒查询状态；查询仍为等待时需取消后重新开始。创建事务响应丢失且未取得事务 ID 时无法在前端定位撤销，后端最多五分钟的期限仍有效，不用自动重建循环掩盖这一情况。

原页面返回只接收 `returnTo=team-new`，或 `returnTo=team-detail&teamId=<既有内部队伍编号>`；丢弃其他参数，未知或失效目标回个人中心。返回只恢复位置，由用户重新确认原操作。绑定冲突只说明申诉入口尚未开放，不调用不存在的接口。

H5 不显示正式核验入口；直接访问原生页面地址时只说明小程序开放范围，不请求核验接口。浏览器组件装配可检查窄屏和状态布局，但不能证明微信原生输入、软键盘、地址栏、安全区或真机行为。`campus-controller.test.mjs`、`campus-client.test.mjs`、`campus-page.test.mjs` 覆盖平台替身；`apps/api/test/campus-uni-client.e2e-spec.ts` 使用实际消费端源码、HTTP 路由和独立 PostgreSQL，只有学校传输是替身。真实学校、开发者工具、iOS/Android 与生产验收仍分别记录，联合环境沿 #140 承接。

## HTTP 与调用顺序

统一前缀 `/api/v1/campus-verification`。只有 `GET /policy` 可匿名访问，其他接口使用现有 Bearer 会话。所有响应及错误均为 `Cache-Control: no-store`。

| 方法与路径                      | 行为                                                                   |
| ------------------------------- | ---------------------------------------------------------------------- |
| GET /policy                     | 当前独立告知版本与全文                                                 |
| GET /                           | 当前资格、当期配置、告知版本及是否可新核验                             |
| GET /profile                    | 本人学校账号编号与登记姓名，只读；无资料为 `{profile:null}`            |
| POST /transactions              | 输入 `{consentVersion}`，返回平台事务与验证码                          |
| POST /transactions/{id}/captcha | 无输入字段；刷新验证码，不延长总期限                                   |
| POST /transactions/{id}/submit  | 输入 `{account,password,captcha,challengeVersion}`，仅一次学校密码提交 |
| GET /transactions/{id}          | 原有效平台会话查询安全状态与成功时的资格快照，不含学校资料             |
| DELETE /transactions/{id}       | 无输入字段；取消原会话事务，已提交终态不改写                           |

先展示告知并取得用户同意，再创建事务并展示验证码。刷新后只能提交最新版本。学校未提供可靠有效期，不能承诺验证码在平台五分钟期限内始终有效。失败、超时或刷新失败需新建事务；请求超时先查询原事务，不盲目重放密码。`processing` 与终态的重复提交只返回状态，不产生新学校请求。

事务仅属于创建者及稳定平台 `sessionId`；访问凭据正常轮换不改变归属，其他平台会话即使属于同一账号也返回404。跨用户、跨会话与不存在均为404；绑定冲突统一409，不说明冲突账号。字段白名单拒绝伪造主体、编号、姓名与资格。详细 DTO 和错误响应见生成的 OpenAPI。

`/auth/me`、昵称更新摘要、校园查询及 `CampusProvider` 使用同一资格计算；成功事务保存当时的安全资格快照，当前资格必须重新读取。学校资料只通过本人 `/profile` 返回，不附加到登录、公开用户、比赛、队伍或联系人响应。没有资料写接口或管理员资料入口。

## 配置与单实例部署

默认 `CAMPUS_VERIFICATION_ENABLED=false`。关闭时不建立学校连接，终止活动事务；未过期旧资格仍有效，密钥存在且会话有效时仍可读取本人旧资料。缺少真实资源与治理等提供者时，`SENSITIVE_BUSINESS_ENABLED=true` 仍拒绝启动；核验成功不会开启演示组队。

开启前通过受保护的服务端环境注入以下配置，不放入仓库、镜像层、日志、前端、URL 或命令历史：

- `CAMPUS_TERMS`：JSON 数组，每项为唯一 `id`、带时区的 `startAt`、`endAt`；转换为UTC，区间 `[startAt,endAt)`，禁止重叠。真实学期由运营配置。配置有效但不在任何当期时，不允许新核验。
- `CAMPUS_POLICY_VERSION`：正整数，告知内容改变时同步提升版本。客户端必须展示最新告知并重新同意。
- `CAMPUS_SUBJECT_HMAC_KEY`：独立随机32字节密钥的标准 base64。HMAC-SHA-256 输入是 JSON `[source,subject]`；索引双向唯一，过期不释放。不能直接换键，否则旧索引无法匹配；轮换须独立迁移。
- `CAMPUS_PROFILE_KEYS`：JSON 对象，键为 `keyId`，值为随机32字节资料密钥的标准 base64；`CAMPUS_PROFILE_KEY_ID` 指定当前写入键。资料密钥不能与 HMAC 密钥相同。启用时须有可用写键；旧键在资料迁移与备份恢复需要期间继续保护。
- `CAMPUS_RATE_SUBMIT_USER/SOURCE/GLOBAL`：滚动15分钟预算，默认5/100/500；`CAMPUS_RATE_CHALLENGE_USER/SOURCE/GLOBAL`：滚动1分钟预算，默认5/100/500。创建与刷新共用挑战预算，学校失败同样计入已准入预算。来源按框架已解析客户端IP的HMAC标识，适当配置可信代理，不信任任意客户端自报来源。预算存库并受统一锁保护。

当前已确认的学期为 `2026-2027-1`：北京时间 2026年9月7日至2027年1月18日（含结束当天）。后端统一配置如下，前端从资格接口读取，不另设日期；结束边界使用次日零点，以包含1月18日全天：

```dotenv
CAMPUS_TERMS=[{"id":"2026-2027-1","startAt":"2026-09-07T00:00:00+08:00","endAt":"2027-01-19T00:00:00+08:00"}]
```

该日期已同步至 `apps/api/.env.example`；实际运行仍需在 API 环境配置中设置并重启，更新模板不会自动修改已有 `.env` 或部署容器。下一学期需另行确认区间，不从月份推算；学期配置本身不会开启校园核验。

首次上线保持入口关闭并先执行增量迁移。`compose.deploy.yaml` 显式从服务器受保护的 `.env` 向 API 注入微信登录、核验开关、学期、独立密钥及限流配置，模板见 `deploy/.env.example`；默认均关闭，微信适配器固定为 `real`，密钥不注入数据库或 Web。部署控制面与联合验收由 #140 承接。仅上传 `.env` 不会更新已有容器，必须重新创建 API，并使用同一 HMAC 键和所需资料旧键；已有受管版本的环境改动会影响配置指纹，须按维护流程验证旧配置及回退方案，不能绕过漂移检查。首期严格限单实例，五个学校操作共享在途准入，最多128个活动事务，无持久队列或密码自动重试。多副本需要专项改造会话路由、全局准入和生命周期清理，当前不支持。

直接运行 API 默认 `API_TRUSTED_PROXY_CIDRS` 为空，忽略客户端转发头。正式 Compose 不向宿主发布 API 端口，为 Nginx/API 建立专用 `proxy` 网络，数据库只加入独立的内部 `database` 网络；以 `PROXY_ADDRESS_PREFIX` 配置不重叠 /24 网段，API 动态分配地址以兼容并行迁移容器、Nginx 固定 `.3`，只信任 Nginx 的精确 `/32` 地址及最近一跳，忽略更远的转发链；Nginx 使用 `$remote_addr` 覆盖 `X-Forwarded-For`，客户端不能用伪造前缀切换预算。此设置以 API 不能绕过 Nginx 直接访问为前提；增加 CDN、负载均衡或开放 API 端口前须专项调整信任边界，不能直接信任任意代理链。已有部署的网络变化需要受控维护；既有配置漂移门禁应保持拒绝自动替换，不在本任务执行生产网络迁移。真实校园 NAT 仍共享出口预算；来源阈值独立于更严格的用户预算，应依据实际出口流量配置，不能将达到阈值解释为该出口每个账号均有违规。

学校句柄、Cookie 与取消控制器只驻留进程内存，API 关闭立即销毁；数据库不保存句柄、学校主体原值、密码、验证码答案、票据或学校原响应。启动后第一次校园请求或每10秒维护任务终止旧进程活动事务，不恢复学校状态。维护任务也清理超时、入口关闭、失效平台会话及受限账号的活动事务。退出使用 #133 的提交后 `SchoolSessionParticipant.destroy`；限制/注销调用者必须遵循既有生命周期约定，在数据库提交后销毁学校会话，失败按既有机制重试。清理暂时失败不能回滚已提交平台撤销，迟到学校成功仍会被最终复查拒绝。

## 私人资料与数据清理

迁移 `0005_campus.sql` 增加绑定、资格、资料、事务、审计及滑动预算表，不修改旧表数据。收到可信身份后，在统一权限锁保护的一个短事务内重新检查账号 active、原平台会话、平台事务、挑战版本、总期限和当期，再原子写入绑定、资料、资格、成功终态与审计。学校请求期间不持有数据库事务。跨学期必须重新创建，不能将旧挑战静默授予新学期资格；续验失败保留旧资料与资格。

资料以 AES-256-GCM 加密，随机12字节 nonce、认证标签、`keyId` 和版本持久化；AAD 为 JSON `[userId,source,version]`，拒绝跨账号密文替换。解密或认证失败返回安全503，不返回损坏内容。只保存当前一份编号/姓名，同主体成功重验才可替换，保留编号前导零与姓名原值。

同学期重验不延长截止；资格到期不删除资料。生命周期撤销即时撤销资格并取消活动事务。#138 在七天冷静期结束后的正式清理阶段调用已注册清理端口，幂等删除资料、资格、私人事务与校园审计引用，失败回滚并向调用者传播以便重试；此端口不表示正式注销已上线，不提前释放 HMAC 绑定。清理后应调用提交后学校会话销毁。

安全终态保留24小时，安全审计180天，滑动预算15分钟无新活动后清除。审计只保存内部账号/请求引用、事件和安全原因，不含学校原值；不要添加请求体、私人响应、异常 cause、APM 请求/响应采样或代理 body 日志。数据库备份按现有到期策略保留；删除不承诺改写历史备份，恢复流程必须重放已完成删除以免恢复注销资料，该恢复编排随 #138/#140 验收。

回退先关闭入口，再回退兼容服务；保留迁移表、绑定、密文和密钥，不靠删表或丢弃密钥回滚。H5/小程序仅经平台 API；本任务不提供页面，#136 使用生成类型接入告知、本人只读展示及核验流程，H5、mp-weixin、设备及生产验收分别记录。
