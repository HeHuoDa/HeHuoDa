# 统一身份认证与校园核验服务

本模块提供“川农校园账号已验证”结论，不证明学生类别、实名、当前在读、学校背书或操作者本人。学校通信只使用 `@hehuoda/sicau-connectors/auth` 构建入口（基于项目现有爬虫连接器对接 `https://auth.sicau.edu.cn`，不等待学校官方第三方接入），不抓取学籍、成绩或课表。

> **2026-11-18 架构升级与演进边界（[ADR 0011](adr/0011-android-h5-and-sicau-only-auth.md)）**：
>
> - **现行基线代码（#134/#135/#167/#168 + #217）**：`/api/v1/auth/school/**` 已是**匿名的学校唯一登录入口**（不需登录、不需微信）；`/api/v1/campus-verification` 除公开告知接口外仍受平台 `AuthGuard` 保护，作为已登录后的个人核验与资料读取路由保留；`apps/uni` 中 `pages/campus/index` 尚保留 `#ifdef MP-WEIXIN` 历史条件分支，客户端接线由 #221/#222 改造。
> - **M2 目标架构（#128 / #217 / #218 / #221 / #222 / #223 / #224）**：项目已放弃微信小程序与微信登录，**统一身份认证即将升级为 H5 与 Android（签名 APK）的唯一用户登录方式**：
>   - **匿名登录事务（#217，已交付后端）**：客户端无需前置微信登录；匿名创建短期认证事务并取得不可猜测的持有凭证与图形验证码，经 `SchoolAuthClient` 取得可信返回并逐字比对姓名/学号后，原子查找或创建平台账号（并发首登只建一号，默认昵称 **`禾伙搭用户`**）。契约见下文“学校唯一登录”。
>   - **双端会话边界（#218/#220）**：H5 使用内存 Access Token + `HttpOnly` Refresh Cookie（配 `Origin` 与 `X-Refresh-CSRF`）；Android 使用内存 Access Token + Keystore 加密存储 Refresh Token；绝不长期保存学校密码用于静默重登。
>   - **组队能力暂缓**：按 ADR 0011，站内组队、招募与联系方式授权等敏感业务已暂缓，`SENSITIVE_BUSINESS_ENABLED` 保持关闭；登录/绑定通过不表示开放组队。

## 现行交互与 M2 迁移契约

在 M2（#221/#222/#224）完成前，现行基线页面（`pages/campus/index`）仅在旧微信小程序编译目标中提供校园核验入口；改造后将由 **H5 与 Android 共用统一身份认证登录页面**（个人中心及登录入口直达，不再经过微信登录或仅限小程序）。核心交互与安全约束延续以下已确立基线：

页面顶部是盾牌图标、标题与简短状态；未认证/登录时直接显示姓名、学号、统一身份认证密码、验证码四个字段的表单卡片，字段只用框内提示、不显示框上标签但保留无障碍名称，密码默认隐藏并可用眼睛图标切换，验证码与图片同行且点击图片换一张。底部显示当前服务端返回的短说明和默认未勾选的同意项，不提供长说明展开入口，也不保留说明前置阶段。同学期重验不会延长到下一学期，普通失败不撤销原有效资格。

进入页面即读取告知与当前状态（登录/认证），可请求时自动创建一次事务并取验证码，无须先勾选同意；等待验证码时可以填写姓名、学号与密码，提交仍须等验证码就绪。首次状态或告知加载失败时显示“重新查询”，由用户重试后恢复取码，不自动循环创建。入口关闭或无当期配置时不创建；若已有有效登录与资格时，可查看脱敏后的姓名、学号与有效期资料卡。失败、取消或过期后由用户主动重开事务，姓名与学号可保留，密码与验证码必须重填。验证码只能使用平台返回的有界内嵌位图，失败时禁止提交不可见图片的答案。刷新清空旧答案，提交保留密码原值并立即清空页面密码、验证码；这些输入只驻留页面，不进入 Pinia、存储、URL 或日志。

提交携带姓名、学号、密码、验证码、验证码版本与当前告知版本，姓名与学号去掉首尾空格后发送。学校返回后由后端逐字比较填写值与可信返回值，不匹配时页面完整显示“验证失败，姓名与学号不匹配”，不保存资料、不授予新资格，已有有效资料与资格保持原状。告知版本变化时取消勾选并重新读取说明，不自动重发密码。新版说明读取失败时使旧说明失效并禁止提交；重新查询只重读信息，保留原事务，不重复创建验证码事务。

应用切后台立即清密、取消页面请求并停止轮询；恢复仅查询原事务，不恢复旧挑战或重放密码。离页、卸页尽力取消事务；退出或账号代次变化同步清除私人页面，后端通过会话撤销及事务期限收敛。请求结果不明先查原事务，处理中每两秒查询状态；查询仍为等待时需取消后重新开始。创建事务响应丢失且未取得事务 ID 时无法在前端定位撤销；页面显示五分钟后主动重新认证的条件，并阻止提前重建与自动循环。后端最多五分钟的期限仍有效。本地发现验证码或事务到期后清除旧挑战，用户点击重新发起时先确认取消旧事务，再创建新事务；取消结果不明时继续查询，不直接重建。

`apps/uni` 中面向旧微信开发工具的 2026-10-26 历史核验记录仅代表改造前的局部测试（不能代替现行 H5 浏览器与 Android 真机全链路验收）。M2 改造后将由 #225（H5 浏览器全流程）与 #226（Android 真机矩阵）分别验收。

## 基线 HTTP 接口与调用顺序

### 学校唯一登录（匿名，`/api/v1/auth/school`）

M2 唯一用户登录入口，**不使用 `AuthGuard`**，无需前置微信登录。匿名客户端持有事务 ID 与不可猜测的持有凭证（`holderToken`）：仅凭事务 ID 不能查询、刷新验证码或提交。服务端只保存持有凭证的 SHA-256 摘要（`school_login_transactions.holder_hash`），持有凭证只在创建与刷新验证码时下发。

| 方法与路径                                | 行为                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------- |
| POST /auth/school/challenges              | 空请求体；创建 5 分钟事务并返回 `holderToken`、验证码与版本（201）            |
| POST /auth/school/challenges/{id}/captcha | `{holderToken}`；换验证码，不延长总期限、不重建持有凭证                       |
| POST /auth/school/challenges/{id}/submit  | `{holderToken,name,account,password,captcha,challengeVersion,consentVersion}` |
| POST /auth/school/challenges/{id}/status  | `{holderToken}`；查询原事务安全状态，不返回私人原值                           |
| DELETE /auth/school/challenges/{id}       | `{holderToken}`；取消，已提交终态不改写                                       |

契约边界：

- 提交成功返回 `{id,status,expiresAt,reason,credential}`，`credential` 含 `user`（默认昵称 `禾伙搭用户`）、15 分钟 `accessToken`、30 天绝对上限 `refreshToken`、`accessExpiresAt`、`sessionExpiresAt`；`credential` **只在首次成功响应出现一次**，重复提交只回安全状态、不重放密码也不重复签发凭据。
- 该 Bearer 通道供 Android 使用。浏览器**不能仅凭自报端类型**取得 Android JSON refresh token；H5 的 `HttpOnly` Refresh Cookie、`Origin` 与 `X-Refresh-CSRF` 由 #218 承接，服务端选择会话通道的边界也随该票收口。
- 事务归属只看持有凭证摘要，不依赖平台会话；跨凭证、缺失与不存在统一 404。
- 错误一律使用安全枚举：`CAMPUS_STALE_CHALLENGE`(409)、`CAMPUS_TRANSACTION_ENDED`(409)、`CAMPUS_TRANSACTION_BUSY`(409)、`CAMPUS_IDENTITY_MISMATCH`(400)、`CAMPUS_CONSENT_MISMATCH`(400，带 `details.currentVersion`)、`CAMPUS_RATE_LIMITED`(429)、`CAMPUS_UPSTREAM_*`/`CAMPUS_UNKNOWN_RESPONSE`(503)、`CAMPUS_UNSUPPORTED_VERIFICATION`(400)、`ACCOUNT_RESTRICTED`(403)、`CAMPUS_VERIFICATION_UNAVAILABLE`(503)。

学校校方 I/O 永远在数据库事务之外：先取得可信身份，再进入一个短事务完成“查找或创建用户 + 绑定 + 资料 + 资格 + 会话/令牌 + 审计”。同一 `(source,subject_hmac)` 的并发首登由咨询锁串行，`campus_bindings` 的 `(source,subject_hmac)` 唯一约束兜底。受限、注销中与已删除账号拒绝签发新会话，也不会因重新登录而新建账号。

仅开启学校登录（`CAMPUS_VERIFICATION_ENABLED=true`、`WECHAT_LOGIN_ENABLED=false`）时无需 `WECHAT_APP_ID`/`WECHAT_APP_SECRET`；`/auth/refresh`、`/auth/logout`、`/auth/me` 与校园状态读取继续可用。`/auth/wechat/login` 仍受 `WECHAT_LOGIN_ENABLED` 保护，正式下线由 #223 收口。

### 已登录校园核验（历史个人核验路由）

统一前缀 `/api/v1/campus-verification`。只有 `GET /policy` 可匿名访问，其他接口使用现有 Bearer 会话。所有响应及错误均为 `Cache-Control: no-store`。

| 方法与路径                      | 行为                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| GET /policy                     | 当前短说明与版本                                                                           |
| GET /                           | 当前资格、当期配置、告知版本及是否可新核验                                                 |
| GET /profile                    | 本人学校账号编号与登记姓名，只读；无资料为 `{profile:null}`                                |
| POST /transactions              | 空请求体，返回平台事务与验证码；拒绝额外输入                                               |
| POST /transactions/{id}/captcha | 无输入字段；刷新验证码，不延长总期限                                                       |
| POST /transactions/{id}/submit  | 输入 `{name,account,password,captcha,challengeVersion,consentVersion}`，仅一次学校密码提交 |
| GET /transactions/{id}          | 原有效平台会话查询安全状态与成功时的资格快照，不含学校资料                                 |
| DELETE /transactions/{id}       | 无输入字段；取消原会话事务，已提交终态不改写                                               |

先创建事务并展示验证码；用户阅读当前短说明、主动同意后才提交凭据。提交必填姓名（上限128字符）、学号（上限128字符）和当前告知版本；姓名、学号去除首尾空格后不得为空，密码原样发送。告知版本在首次提交检查和实际准入锁内分别核对，不符时不向学校提交密码；处理中及终态先幂等返回安全状态。刷新后只能提交最新版本。学校未提供可靠有效期，不能承诺验证码在平台五分钟期限内始终有效。失败、超时或刷新失败需新建事务；请求超时先查询原事务，不盲目重放密码。`processing` 与终态的重复提交只返回状态，不产生新学校请求。

事务仅属于创建者及稳定平台 `sessionId`；访问凭据正常轮换不改变归属，其他平台会话即使属于同一账号也返回404。跨用户、跨会话与不存在均为404；绑定冲突统一409，不说明冲突账号。字段白名单拒绝伪造主体、学校返回编号与资格；填写姓名仅用于比较，不作为可信资料。详细 DTO 和错误响应见生成的 OpenAPI。

`/auth/me`、昵称更新摘要、校园查询及 `CampusProvider` 使用同一资格计算；成功事务保存当时的安全资格快照，当前资格必须重新读取。学校资料只通过本人 `/profile` 返回，不附加到登录、公开用户、比赛、队伍或联系人响应。没有资料写接口或管理员资料入口。

## 姓名学号匹配与短说明

学校认证成功后、身份提交写入前，分别比较填写姓名与学校姓名、填写学号与学校编号，双方只去掉首尾空格。不转换数字、简繁或内部空格，不识别账号别名，前导零必须一致。只有两个字段均一致才继续既有原子提交，保存学校返回原值，填写值不能补齐或替换资料。

任一不一致返回 HTTP 400、`CAMPUS_IDENTITY_MISMATCH`、文案“验证失败，姓名与学号不匹配”；事务失败终态及审计原因均为 `identity_mismatch`，查询不返回私人原值。失败不新增绑定、资料或资格，原有效资料与资格保持原状，学校句柄沿终态流程销毁。取消、退出、到期及迟到成功继续遵循既有复查规则。

当前短说明：

> 密码、验证码仅用于本次认证，不会保存。学校返回的姓名、学号加密保存，仅本人可见。认证仅核对学校账号信息，不证明当前在读或操作者本人。

此契约不更改学校通信底层规则与主体绑定安全约束。H5 与 Android 登录联调、真机与生产安全开关联合验收分别由 #128（#217–#225）、#226 与 #140 承接；离线平台测试不证明真机或生产通过。

## 配置与单实例部署

默认 `CAMPUS_VERIFICATION_ENABLED=false`。关闭时不建立学校连接，终止活动事务；已有密钥存在且会话有效时仍可按授权读取本人历史加密资料。缺少真实资源与治理等提供者时，`SENSITIVE_BUSINESS_ENABLED=true` 仍拒绝启动。

开启前通过受保护的服务端环境注入以下配置，不放入仓库、镜像层、日志、前端、URL 或命令历史：

- `CAMPUS_TERMS`：JSON 数组，每项为唯一 `id`、带时区的 `startAt`、`endAt`；转换为UTC，区间 `[startAt,endAt)`，禁止重叠。真实学期由运营配置。配置有效但不在任何当期时，不允许新核验。
- `CAMPUS_POLICY_VERSION`：正整数，默认及示例已提升为 **2**。告知内容改变时同步提升版本；部署必须同步实际配置，修改示例不表示生产生效。客户端必须展示最新短说明并重新同意。
- `CAMPUS_SUBJECT_HMAC_KEY`：独立随机32字节密钥的标准 base64。HMAC-SHA-256 输入是 JSON `[source,subject]`；索引双向唯一，过期不释放。不能直接换键，否则旧索引无法匹配；轮换须独立迁移。
- `CAMPUS_PROFILE_KEYS`：JSON 对象，键为 `keyId`，值为随机32字节资料密钥的标准 base64；`CAMPUS_PROFILE_KEY_ID` 指定当前写入键。资料密钥不能与 HMAC 密钥相同。启用时须有可用写键；旧键在资料迁移与备份恢复需要期间继续保护。
- `CAMPUS_RATE_SUBMIT_USER/SOURCE/GLOBAL`：滚动15分钟预算，默认5/100/500；`CAMPUS_RATE_CHALLENGE_USER/SOURCE/GLOBAL`：滚动1分钟预算，默认5/100/500。创建与刷新共用挑战预算，学校失败同样计入已准入预算。来源按框架已解析客户端IP的HMAC标识，适当配置可信代理，不信任任意客户端自报来源。预算存库并受统一锁保护。
- `CAMPUS_RATE_LOGIN_SOURCE/GLOBAL/ACCOUNT`：学校唯一登录的匿名预算，默认100/500/5；挑战计入滚动1分钟档，提交计入滚动15分钟档。`ACCOUNT` 档位按**学号盲索引**（HMAC-SHA-256，与绑定索引同密钥但带独立域前缀）计数，不保存明文学号。

当前已确认的学期为 `2026-2027-1`：北京时间 2026年9月7日至2027年1月18日（含结束当天）。后端统一配置如下，前端从资格接口读取，不另设日期；结束边界使用次日零点，以包含1月18日全天：

```dotenv
CAMPUS_TERMS=[{"id":"2026-2027-1","startAt":"2026-09-07T00:00:00+08:00","endAt":"2027-01-19T00:00:00+08:00"}]
```

该日期已同步至 `apps/api/.env.example`；实际运行仍需在 API 环境配置中设置并重启，更新模板不会自动修改已有 `.env` 或部署容器。下一学期需另行确认区间，不从月份推算；学期配置本身不会开启校园核验。

首次上线保持入口关闭并先执行增量迁移。`compose.deploy.yaml` 显式从服务器受保护的 `.env` 向 API 注入核验与登录开关、学期、独立密钥及限流配置，模板见 `deploy/.env.example`；其中 `WECHAT_*` 为待 #223 下线的历史遗留项，部署控制面与安全开关验收由 #140 承接（且容器网络分段与可信代理设置由 #227 落实）。仅上传 `.env` 不会更新已有容器，必须重新创建 API，并使用同一 HMAC 键和所需资料旧键；已有受管版本的环境改动会影响配置指纹，须按维护流程验证旧配置及回退方案，不能绕过漂移检查。首期严格限单实例，五个学校操作共享在途准入，最多128个活动事务，无持久队列或密码自动重试。多副本需要专项改造会话路由、全局准入和生命周期清理，当前不支持。

直接运行 API 默认 `API_TRUSTED_PROXY_CIDRS` 为空，忽略客户端转发头；该能力保留在 `apps/api/src/config/http-adapter.ts`，只认 `hop === 0` 的可信网段。当前生产 Compose **不启用**专用网络与固定地址：db、api、web 仍同处默认网络，也不注入 `API_TRUSTED_PROXY_CIDRS`，因此 `request.ip` 是 Nginx 容器地址，`CAMPUS_RATE_*_SOURCE` 的来源预算会把全部用户合并计入同一来源。**开启校园核验前必须先完成网络分段并注入可信代理**，否则来源阈值失去区分意义。Nginx 仍以 `$remote_addr` 覆盖 `X-Forwarded-For`，客户端不能靠自报前缀切换预算。网络分段（Nginx/API 专用 `proxy` 网络、数据库独立 `internal` 网络、Nginx 固定地址）作为独立任务推进，须先提供受控维护与回滚路径，不能直接切换运行中的数据库网络；既有配置漂移门禁应继续保持拒绝自动替换。真实校园 NAT 仍共享出口预算；来源阈值独立于更严格的用户预算，应依据实际出口流量配置，不能将达到阈值解释为该出口每个账号均有违规。

学校句柄、Cookie 与取消控制器只驻留进程内存，API 关闭立即销毁；数据库不保存句柄、学校主体原值、密码、验证码答案、票据或学校原响应。启动后第一次校园请求或每10秒维护任务终止旧进程活动事务，不恢复学校状态。维护任务也清理超时、入口关闭、失效平台会话及受限账号的活动事务。退出使用 #133 的提交后 `SchoolSessionParticipant.destroy`；限制/注销调用者必须遵循既有生命周期约定，在数据库提交后销毁学校会话，失败按既有机制重试。清理暂时失败不能回滚已提交平台撤销，迟到学校成功仍会被最终复查拒绝。

## 私人资料与数据清理

迁移 `0005_campus.sql` 增加绑定、资格、资料、事务、审计及滑动预算表，不修改旧表数据。迁移 `0014_school_login.sql` 为学校唯一登录新增独立的匿名事务表 `school_login_transactions`（纯新增表，不改 `0001–0013` 任何结构或数据）：事务在确认学校身份前没有平台账号，`holder_hash` 只存持有凭证摘要，`school_login_one_active_holder` 保证同一持有凭证同时只有一个活动事务，`status` 有值域约束。收到可信身份后，在统一权限锁保护的一个短事务内重新检查原平台事务、挑战版本、总期限和当期，再原子写入绑定、资料、资格、成功终态与审计。学校请求期间不持有数据库事务。跨学期必须重新创建，不能将旧挑战静默授予新学期资格；续验失败保留旧资料与资格。

资料以 AES-256-GCM 加密，随机12字节 nonce、认证标签、`keyId` 和版本持久化；AAD 为 JSON `[userId,source,version]`，拒绝跨账号密文替换。解密或认证失败返回安全503，不返回损坏内容。只保存当前一份编号/姓名，同主体成功重验才可替换，保留编号前导零与姓名原值。

同学期重验不延长截止；资格到期不删除资料。生命周期撤销即时撤销资格并取消活动事务。#138 在七天冷静期结束后的正式清理阶段调用已注册清理端口，幂等删除资料、资格、私人事务与校园审计引用，失败回滚并向调用者传播以便重试；此端口不表示正式注销已上线，不提前释放 HMAC 绑定。清理后应调用提交后学校会话销毁。

安全终态保留24小时，安全审计180天，滑动预算15分钟无新活动后清除。审计只保存内部账号/请求引用、事件和安全原因，不含学校原值；不要添加请求体、私人响应、异常 cause、APM 请求/响应采样或代理 body 日志。数据库备份按现有到期策略保留；删除不承诺改写历史备份，恢复流程必须重放已完成删除以免恢复注销资料，该恢复编排随 #138/#140 验收。

回退先关闭入口，再回退兼容服务；保留迁移表、绑定、密文和密钥，不靠删表或丢弃密钥回滚。`0014_school_login.sql` 的回退边界：只回退服务进程，保留新表与数据（旧服务不查询该表即可运行，已验证）；反向删除 `school_login_transactions` 会丢弃进行中的匿名登录事务，仅在没有活动登录时允许，且属于独立迁移，不在本次范围。H5/Android 仅经平台 API；匿名唯一登录接口由 #217 交付，分端会话与客户端接线见 #218/#221/#222，微信路由下线见 #223，实网准入与安全开关见 #140。验收分层记录：单元测试/集成测试、H5 浏览器模拟（320–430px）、Android 真机全矩阵与生产安全开关验收分别留证，不互相替代。
