# 管理端采集与审核接口

本模块对应 #39、#40，依赖 #37 的管理员 Cookie、Origin、CSRF 与事务审计。管理页面接线由 #173／#46 单独验收；服务端采集包不进入 H5 或微信小程序依赖图。

## 调用与幂等

前缀为 `/api/v1/admin/ingestion`。GET 需要有效管理员会话；PATCH／PUT／POST 还需要允许的 `Origin`、会话绑定的 `X-CSRF-Token`。所有写请求提供非空 `reason` 与 UUID `operationId`。操作者由会话派生，客户端不能指定 reviewer。

每个写动作使用独立 operationId。相同管理员重试相同动作及完整输入，返回原结果；复用标识而改变输入或动作返回409。审核文件内部的 operationId 与 HTTP 命令幂等标识分别表达，不能把批准操作的 HTTP 标识用于导入。成功业务、幂等结果与管理员成功审计在同一事务提交；审计失败时一起回滚。审计查询的 `operationId` 是日志自身标识，`commandOperationId` 关联 HTTP 提交的幂等标识。

参数校验失败400／422，对象不存在404，过期基线、状态或执行锁冲突409，权限401／403；错误沿统一 `ApiErrorDto`，不返回数据库连接或私有配置。

## 来源和扫描

| 接口                         | 行为                                                                     |
| ---------------------------- | ------------------------------------------------------------------------ |
| GET `sources`、`sources/:id` | 固定两院 HTML 来源、有效配置、基线与最近运行                             |
| PATCH `sources/:id`          | 携带 baseline 修改启停或允许的数值预算                                   |
| GET `runs`、`runs/:id`       | 按来源、状态和日期分页查询运行、计数、错误、游标与续跑链                 |
| POST `scans`                 | sourceId、from/to、可选同源 HTTPS url、preview；提交后202返回 requestId  |
| GET `requests/:id`           | 查询受理状态、runId、执行结果和安全错误                                  |
| POST `requests/:id/retry`    | 对失败或中断请求显式重试；有运行则续跑原运行，尚无运行则重放持久化原参数 |
| POST `runs/:id/resume`       | 沿原来源、日期范围和剩余游标续跑；不接受替换运行参数                     |

日期窗口1–366天，默认近90天；来源仅允许当前两个适配器。maxPages 1–10，frequencyMinutes 1–1440；请求数1–200、间隔2000–60000ms、单次超时1000–30000ms、总时长1000–900000ms、响应1024–5242880字节。frequencyMinutes 是来源最小启动间隔，不是可编辑 cron。

扫描由进程内后台执行，受理记录持久化在独立 `ingestion_requests`。202表示事务已保存请求，不表示网站扫描成功。受理状态 completed 表示执行结束；结果中的运行状态仍可能 partial 或 failed。浏览器断开不取消后台执行。接口、CLI 和定时任务使用相同 PostgreSQL 来源锁和全局锁，网络扫描并发保持1；执行时若遇到锁竞争或来源停用，查询请求结果可见失败原因。若运行结果已提交、请求结果尚未提交就崩溃，重启按真实运行结果补记受理结果，不重新扫描。

服务重启识别没有存活执行者的未完成请求，标记 interrupted，不自动重放写请求。请求查询返回原 options；普通运行保留游标，管理员检查后显式续跑。若进程在创建运行前中断，`requests/:id/retry` 使用新的 operationId/reason 显式恢复原参数，不重新推算默认日期范围。有已完成运行或已续跑的请求不重复执行。正常关闭会请求终止当前扫描并等待检查点保存；来源停用在下一请求前停止，不能强杀进程。预览只写独立请求、幂等与安全审计记录，不初始化来源业务配置，也不写采集运行、通知、候选或正式比赛。

## 候选审核与发布

候选和通知的列表、详情、正文版本、证据与正式映射均为受保护查询。原文以 JSON 文本返回，页面须按文本显示，不能直接插入 HTML。正文、来源元数据、原始证据及 formalBefore 都是只读材料；客户端篡改会被拒绝。

流程为读取审核材料 → 保存人工修订 → 批准 → 导入预览 → 导入 → 独立发布。保存修订递增 candidateRevision、保留历史并使旧批准失效。批准只改变候选审核状态，不修改正式比赛；新建或更新草稿保持草稿，更新已发布比赛保持原公开内容，只有匹配预览材料并显式确认后才应用。发布另行检查当前正式数据及发布约束，不能复用导入预览充当发布确认。

审核和提交绑定候选修订、来源版本、targetId、完整正式关系基线及输入内容；正文更新、候选变化、目标被占用、映射或正式关系变化均拒绝旧提交。已导入候选不能通过 HTTP 重新批准或拒绝，拒绝候选必须显式重开或等待正文新版后才能重新审核。CLI 使用既有独立入口，HTTP 身份不取自 CLI reviewer。

`GET candidates/:id/operations` 将人工修订与原审核、导入、发布记录统一分页。人工修订的 kind 为 `revise`，reviewer 为可信管理员 ID；result 包含 targetId、操作理由以及 batch／checkedAt／resolution 的历史快照。后续修订不覆盖旧材料，查询不重复返回历史原文正文。

## 工作台计数

`GET /api/v1/admin/dashboard` 的 pending 统计全部候选中 `status=pending` 的记录，不含已批准、拒绝和已导入；sources 统计已实现的固定来源，包含停用项。草稿和已发布统计正式比赛，空数据返回真实0。各项保留 scope 与 asOf。

## 迁移与回退

先应用既有0001–0006，再顺序执行0007及0008增量迁移。新增表保存请求、幂等命令、人工修订与预览回执，原有通知正文、候选、正式映射和审计不删除。迁移重复执行由 schema_migrations 跳过；旧数据升级与旧 CLI 回归纳入隔离数据库测试。

回退应用时保留新增表和字段，不执行破坏性 down 迁移。关闭采集入口和调度后等待在途执行退出，保留请求、游标、版本、人工修正、正式映射及审计供后续恢复。回退应用不撤销已经明确确认的导入或发布，业务修正必须另行审阅。

CI 使用离线 HTTP 样本和名称以 `_test` 结尾的隔离数据库；接口测试、真实官网、管理浏览器和生产激活分别记录。接口或 CI 通过不表示前端接线、实站采集或生产已通过。
