# 服务端业务权限与账号生命周期接入

本契约由 [#133](https://github.com/HeHuoDa/HeHuoDa/issues/133) 交付。当前只有真实认证数据模块，没有正式校园资格、队伍、申请、邀请或联系方式提供者。生产敏感业务保持关闭，`availability.teaming=false`；测试提供者不能作为正式接通证据。

## 权限矩阵

所有操作都要求有效服务端会话及 active 账号。actor 只能从平台凭据解析，不接收客户端可信 userId、角色、成员或 verified。

| 操作                                                                                     | 额外要求                                                             |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| publishRecruitment / applyToTeam / acceptInvitation                                      | 敏感业务已启用、校园资格有效、真实资源规则成立                       |
| readMemberContact                                                                        | 上述要求，以及所有者 active/资格有效、双方为同队有效成员、所有者授权 |
| editExistingTeam / sendInvitation / removeMember / dissolveTeam                          | 队长身份及对应资源规则，不增加校园资格门槛                           |
| leaveTeam / reject / withdraw / closeRecruitment / revokeInvitation / revokeContactGrant | 对应本人/队长及资源规则，不增加校园资格门槛                          |

资格到期不改写队长、成员或历史关系。已核验不能替代资源权限；邀请不预占名额。真实接受邀请服务仍须在同一事务验证归属、截止、容量和角色。退出、移除、解散与撤销授权后的下一次联系方式读取重新查库，不缓存授权结论。

## 调用与事务边界

从 `BusinessAccessModule` 导入 `BusinessPolicy`。调用 `authorize(tx, accessToken, action, resourceId)` 得到服务端 actor，随后在**同一个 tx 内**执行真实业务读取/写入。resourceId 是待检查目标，不是客户端授予的资源权限。调用者不可先提交授权事务，再用另一连接写入或读取联系人。

```typescript
return database.db.transaction(async (tx) => {
  const actor = await policy.authorize(tx, accessToken, action, resourceId);
  return realBusiness.execute(tx, actor.user.id, resourceId);
});
```

示例中的 `realBusiness` 是未来真实业务提供者，不是当前已交付的服务或 HTTP 接口。

- 首版仅支持 READ COMMITTED；其他隔离级别返回 409 `ACCESS_TRANSACTION_ISOLATION`，避免等待锁后继续使用旧快照。
- 统一先调用 `lockAccessTransaction(tx)`，取得 `pg_advisory_xact_lock(133, 1)`，然后才读取授权数据及取得行锁。已有微信账号创建、会话创建、刷新、撤销遵循该顺序；退出撤销与审计共用事务。授权中的当前时刻在取得锁后采样。
- 未来账号限制、注销、资格撤销、成员/授权/招募/邀请变化均必须先取得同一锁。资格提供者的写入路径也必须遵循，不能仅查询时接入。
- 该锁串行化同一数据库的相关事务，持有至提交/回滚。不能在锁内访问学校网络、等待用户或执行长任务；首版以吞吐成本换取清晰的跨模块锁序，后续按实测拆锁。
- 咨询锁依赖所有相关写入路径配合，不能防止旁路 SQL。接入审查必须同时核对读写路径，不能只检查是否调用授权方法。数据库事务锁依据见 [PostgreSQL 官方说明](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS)。
- 资格和资源提供者必须使用传入 tx，不另开连接；提供者抛错时拒绝操作，由调用方回滚，不能 catch 后视为有效或无资产。

`qualification(tx, userId)` 为内部资格读取端口，未接入时明确返回 `unavailable`；不凭空返回 valid。#135 接入真实实现后需使 `/auth/me` 与核验查询共用同一资格计算。

## 提供者与装配门禁

每个保存个人或业务数据的模块提供 `DataModule` 描述：固定安全模块标识、production/test 类型、能力清单和完整生命周期参与者。当前 `LifecycleModule` 的 registry 工厂只注册 `authDataModule()`，启动时以独立的预期模块清单 `["auth"]` 核对，漏注册即使在认证模式也拒绝启动。后续在该集中装配工厂中显式增加真实模块并同步预期模块清单，必须在 `onModuleInit` 封闭注册前完成，不在启动后动态登记。

启用 `SENSITIVE_BUSINESS_ENABLED` 前，必需能力固定为：`campus`、`resources`、`contact-revocation`、`business-cleanup`、`governance`、`school-sessions`。任何缺失均启动失败，只列安全能力名称。配置默认 false，不能靠环境变量跳过检查。

- 注册表拒绝重复模块/能力、不完整生命周期和未声明的提供者。生产 registry 不接受 test 描述；仅测试代码显式构造允许测试替身的 registry。
- 校园模块提供 `CampusProvider.read(tx,userId)`，返回资格状态和期限；valid 必须有有效截止时刻，截止时刻本身已失效。不得把学校可登录推导为当前在校。
- 业务模块提供 `ResourceProvider.read(tx,actorId,action,resourceId)`，从数据库计算 allowed、isCaptain 与联系方式关系。allowed 对每个操作检查实际本人/队长/资源条件，不能常量放行。联系方式必须明确 sameTeam、双方活动成员和所有者授权；各属于不同队伍不满足条件。
- 业务模块还提供 `hasActiveCaptainTeam`、联系方式即时撤权及成员/未决申请/私人联系方式清理、共享历史匿名化实现。`business-cleanup` 不能只有删除会话的实现；不误删其他成员和公开比赛/通知数据。
- 治理能力只在实际举报受理和处置接通后声明。能力声明是受信源码契约，不是自动证明；#140 还须核对真实接口、治理和运行证据。
- 注册表无法自动发现完全未登记的新增模块。新增持久数据的 PR 必须更新集中装配清单和组合测试；只有关闭开关不代表可以跳过已有真实数据的生命周期注册。

当前认证模式没有组队数据，认证参与者的检查不执行队长判断，这是对实际数据范围的声明；不为未来队伍注册“无队伍/已清理”的空适配器。演示 session/fixture 不迁移、不列入生产清理名单。

## 账号生命周期端口

`AccountLifecycle` 为内部调用接口，不发布注销 HTTP 路由，不执行七天计时或调度。

| 接口                                       | 调用责任与行为                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| checkDeletion(tx,userId)                   | #138 在申请事务调用；真实队长存在活动队伍时 409，随后调用全部已注册模块检查                                                                 |
| revoke(tx,userId,now)                      | 申请注销/限制账号时在同事务撤销全部会话、联系方式授权及相关读取资格；参与者失败整体回滚                                                     |
| restrict(tx,userId,now)                    | active/restricted 账号的内部限制端口，与 revoke 同事务；不把 closing/deleted 改回 restricted；独立 restriction 与撤销注销的合并由 #138 负责 |
| cleanup(tx,userId,now)                     | #138 确认七天期限已过且不可撤销后调用，参与者幂等、失败抛出；没有七天前自行调用该接口的业务入口                                             |
| destroySchoolSessions({userId,sessionId?}) | 平台事务提交后销毁学校临时会话；带 sessionId 仅当前会话，不带则该用户全部会话                                                               |

当前认证参与者即时撤销全部平台会话，清理阶段删除对应令牌与会话；用户、微信绑定的最终释放、审计保留/匿名化及清理进度由 #138 协调，不能把参与者返回当成整账号已删除。未来 #135/#137 的资格、绑定、事务、申诉数据须各自注册；#138 保存逐模块进度、重试及三十天期限，不静默跳过失败。

普通退出只撤销当前平台会话、记录同事务审计，再销毁对应学校临时会话，不额外撤销全部联系方式授权。账号限制/注销的调用者须在提交后调用用户范围的学校会话销毁；#135 负责取消其在途核验事务并拒绝迟到成功，不允许共享包读取平台数据库。

学校销毁失败返回 503 `SCHOOL_SESSION_CLEANUP_PENDING`，仅安全信息，表示**平台事务已经提交**。调用方保留内部用户/会话引用并幂等重试销毁，不重新执行账号状态变更、不重发密码，也不声称平台事务回滚。#135 接入时必须交付该重试/取消适配及组合测试；未接入时不存在待销毁的学校会话。

错误沿现有格式：会话无效401；账号/资格/角色不足403；私人资源缺失或不应暴露404；资源状态/事务冲突409；能力关闭或缺失503。只有查看者可见自己的安全资格原因码；所有者不满足条件统一隐藏为404。

## 接入验收矩阵

后续真实业务 Issue 应链接本文并摘要自己的操作、提供者和事务边界，至少覆盖：

- 四类操作的未登录、账号受限、未核验、过期、撤销、资格来源不可用及资源不足；任何缺失提供者均拒绝。
- 联系方式双方资格、同队关系、活动成员和所有者授权；退出/移除/解散/撤权后下一次查询立即失败。
- 到期队长管理原队伍、成员退出/撤回仍可用；非队长不能借这些入口管理队伍。
- 真实 PG 同步屏障验证业务与注销/限制/资格撤销的两种提交顺序；等待后重查，不使用 sleep 猜测竞争结果。
- 参与者检查/撤权/清理失败传播、审计失败整体回滚、重复清理及失败后重试不误删他人数据。
- 缺少任一能力、重复/漏注册、默认关闭及环境变量硬开拒绝；测试控制器不进入生产 AppModule/OpenAPI。

本票测试使用隔离 `_test` 数据库、随机 schema 和测试专用资源表。真实学校、真实组队、H5/小程序运行及生产开放分别由后续任务验收；本票没有页面变更，两端消费同一平台权限契约，构建或演示不能解除业务开放阻塞。
