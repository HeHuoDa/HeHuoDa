# ADR 0005：uni-app 用户端导航骨架与旧地址映射

状态：Accepted · 2026-10-18 · 关联 [Issue #60](https://github.com/HeHuoDa/HeHuoDa/issues/60)

## 背景

旧 Web 用户端用 Vue Router 的 History 路由、`StudentLayout` 与 `BrandLayout` 组织页面：桌面侧栏、移动端顶栏与底部三栏导航、`document.title` 拼接标题、`/my/teams` 与 `/my/applications` 重定向到个人中心分区。uni-app 没有等价的动态路由：页面必须在 `pages.json` 静态注册，平台主导航用 `switchTab`，普通页面用 `navigateTo`，且 `switchTab` 不能携带 query。迁移还要避免把浏览器 History、`document.title` 或 DOM 当成导航基础设施。

## 决策

1. **页面与标题同源**：`pages.json` 负责注册与原生导航栏标题，`src/navigation/routes.ts` 保存页面路径、标题、主导航/普通页面类型、旧 Web 来源与开发状态。契约测试校验注册表与 `pages.json` 双向一致、标题相同、`tabBar` 三项与注册表一致。
2. **平台主导航用原生 tabBar**：首页 / 找队友 / 我的三项固定底部导航，切换走 `switchTab`；比赛详情、队伍详情、发布招募、收藏、通知、登录注册、404 走 `navigateTo` / `redirectTo`。返回时页面栈只有一页则回首页，避免空栈。
3. **旧地址映射集中登记**：`sourceRoutes` 列出旧 Web 全部路由及目标或“不迁移”原因；`resolveSourceAddress` 解析静态路径、`:id` 动态段与个人中心分区，未知地址返回 404 页。`/my/teams`、`/my/applications` 固定映射到个人中心的队伍/申请分区。
4. **分区交接不依赖 URL**：`switchTab` 不接收 query，`openProfileSection(section, query)` 先写入一次性的 Pinia 状态，交接分区及复制后的合法附加参数。旧地址解析结果分别提供 `section` 与 `query`，固定旧分区不被附加参数覆盖。个人中心首次加载先在 `onLoad` 解析深链，再消费交接；已挂载页面在 `onShow` 或收到新意图时消费，避免默认资料区覆盖首次交接。附加参数保留在页面 `routeQuery`，非法分区回落到资料区并显示提示。
5. **参数规则统一**：缺失、空白、重复冲突、非法业务 ID 都返回明确反馈；uni-app H5 会把重复键合并为 `"a,b"`，因此单值参数按逗号拆分后判定，取值一致接受、不一致判冲突。参数只用于定位展示内容，不代表身份或权限。
6. **H5 入口兜底**：启动时检查一次 hash 是否命中已注册页面，未命中转到 404；小程序页面静态注册，不需要该分支。pathname 级旧地址、刷新与浏览器返回仍由 #82 统一验证。
7. **预留页只搭骨架**：三个主页与后续页面先交付“待开发”占位、标题、说明和入口链；认证页只搭品牌布局，表单与未开放反馈留给 #67，避免与页面任务重复实现。

### 2026-10-21 补充：关于页预留兼容别名

[Issue #77](https://github.com/HeHuoDa/HeHuoDa/issues/77) 要求在新客户端注册独立关于页，并为 [#82](https://github.com/HeHuoDa/HeHuoDa/issues/82) 预留 `/about` 的 pathname 兼容映射。旧 Web 只有个人中心的静态说明，没有 `/about` 成品。`sourceRoutes` 与 `RouteDefinition.source` 因此同时记录既有来源路径和需求明确预留的兼容别名；新增别名须在 `note` 中说明来源，不能将登记映射当作旧端页面已存在或部署兼容已完成。页面注册、统一导航和 #82 的部署验证分工沿用本决策。

## 后果

### 2026-10-23 补充：H5 历史入口与浏览器历史

Issue #82 在 `createApp` 创建 uni 应用前调用 `prepareH5Entry`，按同一份 `sourceRoutes` 转换旧 pathname、query 与赛段锚点，并保留当前 `history.state` 替换为原生 hash 页面。部署层只提供静态回退，移除 #25 的临时 njs 路由表，避免重复映射与丢失浏览器 fragment。API、缺失资源仍优先处理。

H5 运行期间装饰 uni 已安装的 router：校验未知页面、规范化参数、保留同页参数替换时的滚动与统一标题后缀。列表筛选／页码和个人中心分区替换当前历史项；详情仍经 uni 导航新增历史项。页面显示或浏览器路由变更时读取当前参数，继续使用原有页面控制器和 Pinia 一次性交接，不另建业务路由状态。H5 的 DCloud 参数再编码／再解码由显式适配器处理，旧地址与原生地址均只解码一次。微信编译去除这些浏览器分支，仍按原生页面栈、标题与交接机制运行。

- 非 tab 页面不再显示底部导航，H5 顶部由原生导航栏替代旧 Web 顶栏与品牌区；这是平台导航的标准形态，与旧 Web 的差异需在验收中逐项记录。
- 本轮审查后用户明确选择 H5 与微信小程序沿用相同页面、组件与原生导航源码，不恢复 H5 专用的旧 Web 顶栏、侧栏或底部导航。该选择接受上述布局差异；仅保留既有 H5 未知入口检查等必要平台适配。
- tabBar 目前只有文字：图标资源与尺寸属于 #62；tabBar 的边框、高度与选中样式由平台决定，无法完全复刻旧 Web 的浅绿选中块。
- H5 浏览器标签标题为 `navigationBarTitleText`，不再拼接“· 禾伙搭”；统一标题后缀属于 H5 兼容层，留给 #82。
- 个人中心分区在当前会话内保留；tabBar 再次点击“我的”不会强制回到资料区，与旧 Web 每次进入 `/profile` 重置的行为略有差异。
- 新增业务页面只需注册页面并补一条注册表定义；跳转、标题、参数与旧地址映射沿用同一套入口，不另建路由状态。
- 微信开发者工具、真机、键盘、安全区域与系统大字号仍由 #85 集中验收，H5 浏览器模拟不能替代。

## 备选方案

- **自定义 `StudentShell` 组件**：能完整复刻旧 Web 的顶栏、底部导航与详情页导航，也能让参数直接随页面传递；代价是自行处理安全区、层级、页面栈与小程序非标准形态，并持续维护两套导航行为。选择原生 tabBar 换取平台一致性和更低的维护成本。
- **保留 vue-router 或 H5 专用路由层**：与 uni-app 页面模型冲突，且不能用于小程序；只作为 #82 的 H5 兼容补充，不作为页面导航基础。
