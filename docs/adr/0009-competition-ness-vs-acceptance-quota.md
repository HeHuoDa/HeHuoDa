# ADR 0009：赛事性质与验收口径分离

## 状态

采用

- 日期：2026-11-05
- 关联：Issue #179（质量集验收）、ADR 0004（官方通知候选与正式比赛分离）

## 背景

#179 要求一份独立真实质量集，用于评估采集与分类的真实表现。冻结这份质量集时遇到一类判断：某条通知**确实是赛事**，但只面向研究生（如「中国研究生智能建造创新大赛」），而本项目主要服务本科生，这条不计入本科生正例配额。

当时的处理是把它的 `classification` 记为 `non_competition`，另用 `trueNature=competition`、`excludedBy=graduate-only-scope` 保留赛事性质。质量集随即冻结，准确率、混淆矩阵与配额核对都基于这个标注。

这个处理暴露了一个建模错误：`classification` 本来只回答「内容是否属于赛事」，现在被用来回答「是否计入某项验收的配额」。两个问题被压进一个字段后：

- 产品侧若沿用该口径，会把真实赛事从研究生用户眼前抹掉，而研究生同样是平台用户；
- 报告里的「误判明确 5 条」实际混合了真正的分类错误（正文旁证被当成赛事声明）与口径排除（研究生赛事），无法分别追责；
- 后续执行者若照此模型继续标注，会把错误沿用下去。

## 决策

**验收口径不灌入产品分类。** 具体三条：

1. **`classification` 只描述内容性质。** 只面向研究生的赛事仍是 `definite`；是否计入本科生正例配额由独立字段表达，不由分类承载。

2. **已冻结的质量集不回改。** `labels.frozen.json` 保持原样。冻结的意义是不能在发现缺陷后按结果修正答案——那正是冻结准入要防的事。该集的建模缺陷记在本 ADR 与 `protocol.md` v2 中，供后续执行者识别。

3. **干净验证集按正确模型标注。** 下一轮独立验证集用「分类 + 人群口径 + 配额计入」三个独立字段标注，并单独报告分类准确率与配额达成情况。

## 后果

**代价**：已发布的 91.3% 等指标带开发偏差，且其中「误判明确」一项含义不纯，不能直接作为 #179 第 5 条的验收证据。要得出可信结论，需要另建未参与调参的验证集。

**收益**：产品侧的分类语义保持干净，不会因为验收口径而删掉研究生赛事；报告能把「分类错误」和「口径排除」分开统计，缺陷可归因。

**后续**：新增人群口径字段需要动 DTO 与生成类型，属独立实现任务，不在本 ADR 范围内落地。

## 相关判断

同一次访谈还确认了两条与分类精度直接相关的规则，一并记录，避免后续把有意的取舍当缺陷修：

- **正文旁证不足以确认赛事。** 标题未出现赛事词时，正文命中只能判到疑似，不能直接判明确。标题是发布方对通知性质的自我声明；正文常列举、引用、举例。已实测：海外访学招生、实验室招新、硕士招生宣传、党员发展通知都因正文提到「竞赛」而被判成赛事。
- **变更通知只按标题判定。** 正文里「如有调整」这类泛指会把首次发布的通知误判成补充通知。已知代价是标题无变更词、但正文明确写「推迟至某日」的通知会漏判；本轮实测 1 条。接受该漏判，优于引入一批新误判。
