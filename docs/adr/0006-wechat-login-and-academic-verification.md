# ADR-0006：微信登录与组队业务教务核验分离

- 状态：部分采纳。微信登录与平台凭据部分已随 [Issue #131](https://github.com/HeHuoDa/HeHuoDa/issues/131) 实现并采纳；教务核验部分仍为 Proposed，待决事项由 [#134](https://github.com/HeHuoDa/HeHuoDa/issues/134)/[#135](https://github.com/HeHuoDa/HeHuoDa/issues/135) 决策。
- 日期：2026-10-22 提出；2026-10-24 登录部分定稿。

## 背景

校园组队需要防范冒充及诈骗，同时希望降低日常登录成本。2026-10-22 的需求澄清中，用户明确选择：微信负责小程序登录；用户填写教务账号和密码，由后端爬虫登录教务系统获取资料进行校园身份核验。相较仅填写姓名、学号或验证校园邮箱，方案希望借助教务来源核对身份；代价是新增凭据处理、来源可用性和访问边界风险。

两类问题此后被确认应分别决策、分别交付：登录负责"这是哪个平台账号"，教务核验负责"这个账号关联的学校身份是否被核对过"。把两者捆在一起会让登录交付被学校侧研究（[#130](https://github.com/HeHuoDa/HeHuoDa/issues/130)）阻塞，也会诱导把"能够登录教务账号"混同于"当前在校学生"。

## 决策：微信登录与平台凭据（已采纳）

- 用户端以微信小程序登录为唯一登录入口；用户主动登录后首次自动创建平台账号，后续登录定位同一账号，不存在邮箱密码注册或公开管理员注册。账号默认昵称为"微信用户"，仅本人可改为 trim 后 1–20 字。H5 不新增登录渠道，保留公开浏览与演示。
- 平台凭据是一对高熵随机 Bearer 令牌：访问凭据 15 分钟有效，刷新凭据随登录/每次刷新轮换，会话绝对上限 30 天且刷新不延长。数据库只保存令牌 SHA-256 摘要；已消费刷新凭据再次出现即撤销整个会话族，退出撤销当前会话，账号状态每次请求由数据库校验、即时生效。
- 登录需要用户确认当前平台协议版本；版本不匹配不能建立账号。微信 code 仅由服务端向官方固定端点兑换一次，不自动重试、不下发 session_key，UnionID 可空且不作为跨应用合并依据。
- 微信登录默认关闭，由环境开关控制；关闭时登录与刷新明确返回服务不可用，公开接口不受影响。登录与刷新失败有来源/账号/全局三档限流预算。
- 旧演示资料（学籍、联系方式等）不写入真实账号；校园核验状态在核验模块接入前恒为 unverified，`availability` 只表达真实开放的能力。

与原设想的差异：计划书早期草案采用"邮箱密码 + 服务端 Cookie Session + CSRF"。由于用户端迁移到 uni-app 小程序（ADR-0002）且用户选择微信登录，Cookie/CSRF 方案被放弃，改为上述 Bearer 凭据轮换；该差异由本 ADR 与项目计划书同步固化。

## 决策：教务核验（Proposed，未实施）

以下四类操作必须检查校园身份核验结果：发布招募、申请加入队伍、接受邀请入队、查看成员联系方式。联系方式仍须同时满足原有领域规则：查看者和所有者均为同队有效成员，并获得联系方式所有者授权；教务核验不替代这些权限。

当前仅确认核验渠道和权限边界。待决事项（由 #134/#135 决策，本 ADR 不预设结论）：

- 核验时机、有效期及风险触发的重新核验规则。
- 最少采集、留存的身份字段，教务凭据及临时登录态的处理与销毁方式。
- 教务不可用、账号错误、验证码及无法取得在校属性时的状态和处理路径。
- 支持的学生类别、校友范围及对应教务系统。
- 身份唯一绑定、账号冲突、微信换绑、找回及注销规则。

不能将"能够登录教务账号"直接解释为"当前在校学生"或"申请者必然为账号本人"。实现前须核实实际教务来源、接口或页面契约、学校系统访问规则和个人信息处理边界。当前仓库的公开通知采集不作为私人教务账号访问能力的证明；本 ADR 不授权绕过验证码或访问限制。

## 后果

登录侧的严格撤销（轮换后旧访问凭据即时失效、重放撤销整族）会让客户端在并发刷新窗口内收到更多 401，前端必须实现单次刷新协调（由 [#132](https://github.com/HeHuoDa/HeHuoDa/issues/132) 承接）。凭据与审计存于数据库使会话不随进程重启丢失，也让认证路径新增数据库读写开销。限流固定窗口实现简单，跨窗口边界的突发可能达到两倍预算；如需严格平滑再引入滑动窗口。

教务核验仍未定案前，组队相关能力对全部账号保持未开放（`availability.teaming=false`），不存在虚构的已核验状态。

## 实施记录

- 2026-10-24：#131 落地五接口（`POST /auth/wechat/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /auth/me`、`PATCH /auth/me`）、`0004_auth.sql` 迁移（users、wechat_identities、auth_sessions、auth_tokens、auth_audit_logs、auth_rate_limits）、离线微信替身与真实兑换适配器、默认关闭的 `WECHAT_LOGIN_ENABLED` 及限流/审计/到期清理；契约经 OpenAPI 生成供 #132 消费。真实微信联调（AppID/AppSecret/HTTPS 域名/真机）为环境验收条件，未完成前不声称生产可用。
- 2026-10-25：#132 落地小程序端接入：微信一键登录（登录前确认协议版本）、刷新凭据只写小程序存储、访问凭据仅内存、冷启动恢复、并发 401 单次刷新与写请求不盲目重放、认证代次隔离账号切换的迟到响应、真实账号昵称入口与退出清理。因 `wx.request` 不接受 PATCH，新增 `POST /auth/me` 别名（与 PATCH 共用服务与校验）并在 OpenAPI 中声明；H5 保留公开浏览与“服务未开放”反馈，不调用微信接口、不保存凭据。开发者工具与真机仍未验证。
