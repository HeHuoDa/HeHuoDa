# ADR 0004：官方通知候选与正式比赛分离

- 状态：采用
- 日期：2026-10-11
- 关联：Issue #23，依赖 Issue #22 / ADR 0003

## 背景

学院通知可能转载、改期、混合多个赛段，也可能只有材料截止或不完整资格。直接把采集结果写成正式比赛会让旧公开数据失效，且无法追溯人工依据。当前没有管理员认证与编辑界面，首批只处理信息工程学院、生命科学学院的公开 HTML。

## 决策

在现有 API 内实现调度与适配器，维护者通过 CLI 执行采集、修正、批准、导入和发布。PostgreSQL 独立保存来源、运行游标、不可变通知版本、候选修订、正式映射与操作日志。默认关闭调度，启用后每天北京时间 09:00、18:00 执行；所有 API/CLI 进程使用同源及全局会话锁，网络并发为 1，并限制页数、请求、时间与响应大小。

采集仅写候选。发布单位、承办学院、参赛资格和报名/材料/比赛时间分别提取并保留证据；无法确定的字段保持未知。转载只提供人工关联提示。新版重新进入审核，来源失效只标记需要核对，已公开比赛继续使用原正式数据。

审核文件绑定来源版本、候选修订、原文及元数据、正式比赛与全部关系摘要。批准与导入在事务内锁定并校验，复用原人工导入器的校验及关系更新规则；正式写入、映射和操作日志共同提交或回滚。导入器保留独立入口，并提供调用方持有事务的核心函数，避免嵌套提交。新增草稿与修改草稿可在批准后导入；修改已发布内容须先审阅同一文件的预览再显式确认，不能退回草稿；发布是独立操作。相同操作及输入幂等，过期输入拒绝。

每次连接前校验 DNS 的全部结果并固定实际连接地址，每次跳转重新校验来源白名单和 robots，保持 TLS 域名验证。对本机 FakeIP 提供仅限固定来源及经核实公网地址的可选配置，不放行保留地址。完整响应默认 30 天清理，正文、证据、人工修正与审计长期保留；报名者名单不进入候选和响应存储，附件只记录链接。

## 取舍与后续

与直接导入草稿相比，独立候选增加表与版本校验，但保留既有公开数据，并能区分采集、人工判断、导入和发布。与新增管理服务相比，CLI 复用现有 API 与数据库，减少当前认证及部署范围；操作身份是维护者填写的审计标识，访问控制由运行环境和数据库权限承担，不能当作管理员认证。

10 页上限意味着一次扫描可能部分完成；游标与非零退出码要求维护者检查并续跑。结构化规则仍需人工确认年份、多赛段与资格，不能声称自动理解任意官网。未来扩展来源、管理界面和权限须另行设计。源码测试离线运行，真实网站验收单独记录，不让 CI 依赖官网。

当前不改公开查询契约。服务端 Node HTTPS、HTML 解析、数据库锁和调度不迁移到 uni-app；H5 请求地址/CORS、微信小程序合法域名、来源 web-view 及复制入口仍需目标端验证，见迁移待办。新增迁移不删除正式数据，关闭调度和回退应用时保留全部表，避免自动破坏审计。
