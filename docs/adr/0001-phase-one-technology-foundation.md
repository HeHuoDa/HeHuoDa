# ADR 0001：阶段一工程基础

状态：Accepted · 2026-10-01；Web 组件与样式决策于 2026-10-03 被 [ADR 0002](0002-student-styling-and-uni-app.md) 部分替代。

下文保留阶段一采用 Vant 的历史背景；当前 Web 已移除 Vant，其他工程基础决策继续有效。

## 背景与决策

禾伙搭的前后端将共同演进，接口契约需要同步且可重复生成。阶段一采用 pnpm 单仓工作区：Vue 3、Pinia、Vant 和 Tailwind 构成 Web；NestJS 与 Fastify 构成 API；OpenAPI 生成仅含类型的共享包，Web 通过 `workspace:*` 消费。

选择单仓以便接口修改、类型生成和前端适配进入同一次审查，代价是工具链升级与质量门禁需要协调。Pinia 管理页面共享状态，接口契约由 API 的 DTO 与 Swagger 定义，避免前端手写一套平行类型。

阶段一只验证工程运行、健康状态与协作流程，暂不接入数据库。比赛届次、招募、申请与联系方式授权仍需按业务计划设计；避免在模型未定时固定持久化结构。

## 后果

- 同一提交可以验证 API 与 Web 类型一致性，CI 会检查生成文件差异。
- DTO 的装饰器元数据成为契约生成前提，生成脚本使用 TypeScript 编译后运行。
- Web 与 API 可分别构建，但需统一维护工作区锁文件；依赖升级应检查各工具声明的兼容范围。
- 当前健康检查只代表应用进程可响应，后续数据库接入后需另行定义就绪检查。
