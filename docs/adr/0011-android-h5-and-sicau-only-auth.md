# ADR 0011：收敛用户端为 Android／H5 并以川农统一身份认证作为唯一登录

- 状态：Accepted（采纳）· 2026-11-18 · 关联 [Issue #213](https://github.com/HeHuoDa/HeHuoDa/issues/213)（同步 #38、#46、#58、#83、#84、#86–#88、#90、#128、#140、#143、#214–#228）
- 替代关系：本决策替代 [ADR 0006（微信登录与组队业务教务核验分离）](0006-wechat-login-and-academic-verification.md) 中的微信主账号、微信小程序唯一入口、H5 无登录与先微信后核验前提；同时更新 [ADR 0002](0002-student-styling-and-uni-app.md)、[ADR 0003](0003-competition-catalog-persistence.md)、[ADR 0004](0004-official-notice-ingestion.md)、[ADR 0005](0005-uni-navigation-shell.md) 与 [ADR 0008](0008-admin-cookie-auth-and-atomic-audit.md) 涉及的目标端与学生认证说明。

## 背景

原规划将用户端（`apps/uni`）同时指向 H5 与微信小程序，并以微信小程序微信登录作为唯一主账号入口，再在登录后通过川农统一身份认证完成校园核验（ADR 0006）。实际演进中存在以下约束变化：

1. **微信小程序交付阻塞与优先级变化**：小程序主体、类目审核、合法域名配置及微信开发者工具/双平台真机适配持续引入外部审核阻塞，而平台首期核心价值在于“管理员快速维护、审核并发布准确比赛信息 + 学生在手机/浏览器可靠浏览比赛”。
2. **学校接入与历史数据前提明确**：本项目尚未对外开放上线，不存在需要保留或认领的历史微信用户资产；同时学校官方 OAuth/CAS 第三方接口短期内不可依赖，而仓库内 `@hehuoda/sicau-connectors/auth`（#130/#134）已具备基于网页登录流程核实可信校园身份的能力。
3. **跨端分发路径简化**：学生移动端可通过受控 HTTPS 入口直接下载签名 Android APK 安装使用，无需应用商店上架、热更新或同步支持 iOS，从而将有限研发与测试精力集中在管理闭环、H5 与 Android 双端质量及账户会话安全上。

## 决策

### 1. 产品与平台范围收敛

1. **目标用户端**：保留普通 uni-app（Vue 3）工程 `apps/uni`（不切换 uni-app x，不重建客户端），目标收敛为 **H5** 与 **Android（仅自有官方站点或受控 HTTPS 入口下载签名 APK，不上架应用商店、不引入热更新）**。
2. **明确放弃范围**：放弃微信小程序（`mp-weixin`）、iOS 客户端与微信登录；**不实施**历史微信账号迁移、账号认领、历史绑定合并或旧微信客户端会话兼容。已关闭的微信小程序专项任务（如 #85、#89）保持关闭不重开，残留微信接口与条件分支在 M2 专项任务（#223、#224）收尾清理。
3. **优先上线与暂缓边界**：
   - **M1 优先上线**：管理员登录管理端 → 手工创建/编辑/预览/发布/隐藏真实比赛 → H5 游客无需登录即可浏览比赛列表、详情、赛段与官方外链；`apps/admin` 通过 `/admin/` 子路径整合进 Web Nginx 镜像部署（不新增独立 Node 服务）。
   - **M2 用户登录**：H5 与 Android 接入川农统一身份认证唯一登录及各自安全的 Refresh Token 持久化/传输机制。
   - **M3 首期发布**：完成正式签名 Android APK 分发、运维准入与多版本 API 兼容基线。
   - **暂缓范围**：站内组队、招募发布、申请/邀请、队伍管理、举报治理对接（#41/#216）以及 27 院官方通知自动采集规模化运营前置（#49/#178/#179/#206）在本期暂缓；已建成的 `packages/sicau-connectors/notices` 与采集/审核/导入/发布能力作为可用辅助基础保留，但不阻塞手工比赛上线。

生产同源路由拓扑收敛为：

```text
https://<正式域名>/          → apps/uni H5
https://<正式域名>/admin/    → apps/admin 管理端静态产物
https://<正式域名>/api/v1/   → apps/api NestJS / Fastify API（生产不注册 /docs）
```

### 2. 跨任务冻结契约：手工比赛外链规则

管理员在管理端手工录入或编辑比赛的官方通知、报名说明参考外链时，适用以下统一规则（供 #38、#46、#214、#219 等任务共同遵守）：

- **协议与格式**：仅允许**无凭据（无 `username` / `password`）、无非默认端口（省略端口或标准默认 HTTPS 端口，拒绝显式非标准端口）、采用公开 DNS 域名的 `https://` URL**（**不再限于 `*.sicau.edu.cn`**），由管理员人工核实其确为赛事官方来源。
- **仍拒绝的输入**：拒绝 `http://`、userinfo、IP 字面量（IPv4/IPv6/数字 IP）、`localhost` 或单标签内网名、保留地址、显式非默认端口、空白/控制字符、反斜杠及破损转义。
- **严格边界**：该规则**仅适用于管理端手工维护渠道与用户端安全打开（H5 新标签页安全打开、Android 调用系统浏览器）**；**严禁**放宽 `packages/sicau-connectors/src/notices` 与官方通知自动采集入库白名单（自动采集与附件下载仍严格限制在仓库已注册且经核验的 `https://*.sicau.edu.cn` 栏目及路径）。
- **现行代码差异注记（待 #38/#214/#219 落地对齐）**：本 ADR 确立时（`e88901c`），`apps/api/src/competitions/import.ts` 仍校验 `sicau.edu.cn` 域名，`apps/admin/src/console/review.ts`（`safeSourceUrl`）与 `apps/uni/src/source/policy.ts`（`parseSourceUrl`）对历史采集/展示入口仍包含 `http:` 或端口放行分支；后续比赛管理与用户端外链任务须按本节契约收口手工比赛外链校验。

### 3. 跨任务冻结契约：川农唯一登录与默认昵称

1. **连接器路线**：用户登录**仅使用**基于项目自有爬虫连接器 `@hehuoda/sicau-connectors/auth`（`SchoolAuthClient` 对接 `https://auth.sicau.edu.cn` 的 `sicau-cas` 网页流程）的川农统一身份认证，**不等待学校官方第三方 OAuth/CAS 接入**，也不要求前置微信登录。若未来学校提供可用官方授权方式，可在连接器适配边界平滑评估替换。
2. **匿名事务与身份核对**：
   - 匿名客户端发起登录时，先向服务端申请短期认证事务并取得**不可猜测的持有凭证**（禁止仅凭事务 ID 查询、刷新验证码或提交）以及图形验证码。
   - 用户阅读当前短说明、同意协议并手填**姓名、学号、统一身份认证密码与验证码**；服务端调用连接器取得学校可信返回后，在原子写入前**逐字比对（仅忽略首尾空格）**用户填写姓名/学号与学校返回的 `name`/`accountNumber`。
   - 比对通过后，按 `(source, subject_hmac)` 原子查找或创建平台账号（并发首次登录仅创建单一账号），同步使用 AES-256-GCM 加密留存最新一份学校姓名与学号（仅本人只读）。
   - 多身份账号维持 `unsupported_verification` 安全拒绝策略；**登录成功不自动等同于当前在读或本科生身份，也不直接开放已暂缓的敏感组队能力**。
3. **默认昵称**：首次通过川农统一身份认证建立的平台账号，默认昵称统一为 **`禾伙搭用户`**（取代原 `"微信用户"`），仍支持用户本人修改为 trim 后 1–20 字符的昵称。
4. **降级边界**：学校认证服务不可用或配置关闭时，公开比赛列表、详情与官方来源查阅保持完全可用，认证页明确展示服务异常提示，不静默建号或伪造成功。

### 4. 跨任务冻结契约：双端会话与安全边界

M2 改造沿用数据库高熵随机凭据、SHA-256 摘要存储、15 分钟 Access Token、30 天绝对上限 Refresh Token 单次轮换与重放撤销机制，并按目标端差异化落地存储与传输契约：

| 维度          | H5 端                                                                             | Android APP 端                                                             |
| ------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Access Token  | 仅驻留内存（不写入 `localStorage` / `sessionStorage`）                            | 仅驻留内存                                                                 |
| Refresh Token | 服务端 `HttpOnly`、生产 `Secure`、`Path=/api/v1/auth`、`SameSite=Lax` Cookie 管理 | 平台 JSON 响应返回后，通过经验证的 **Android Keystore 加密存储适配**持久化 |
| 降级策略      | Cookie 被浏览器策略阻断或失效时要求重新登录                                       | 若安全存储不可用，明确降级为本次内存会话并提示重启需登录，禁止明文落盘     |
| CSRF / Origin | Cookie 参与的登录、刷新、退出端点强制校验精确 `Origin` 与 **`X-Refresh-CSRF`**    | 使用 Bearer 凭据协议（客户端自报端类型不授予额外特权）                     |
| 多端/刷新协调 | 协调同源多标签的单飞刷新，兼顾正常并发与重放撤销，具体边界由 #218/#221 验证       | 保证并发 401 单飞刷新，冷启动/后台恢复核验本地加密刷新凭据                 |
| 退出与清理    | 请求撤销服务端会话并清除 Cookie，清理客户端内存与私人状态                         | 同时清理本地 Keystore 存储并撤销服务端会话，失败提供重试与明确反馈         |

- 仅支持用户主动登录、刷新轮换与主动退出；**严禁**长期保存学校密码用于后台静默自动重登。
- 管理员继续独立使用 `admin_accounts`、`hh_admin_session` Cookie、精确 `ADMIN_ALLOWED_ORIGINS` 与 `X-CSRF-Token`，与学生会话完全隔离，互不转换或代换。

### 5. 跨任务冻结契约：暂缓入口方案 B 与会话内临时收藏

1. **三栏导航与暂缓提示（方案 B）**：M1 保留 `apps/uni` 原生三栏 `tabBar`（首页 / 找队友 / 我的），避免改动核心导航框架引发页面回归；将「找队友」主 Tab 页、发布招募、队伍详情以及首页比赛详情中的关联招募/演示互动入口收口替换为**温和的暂缓提示说明**（明确当前仅开放比赛信息发现，组队与招募功能暂未开放，不展示可操作的虚假队伍/申请/举报演示）。
2. **会话内临时收藏**：`pages/my/favorites` 与比赛详情收藏按钮继续保留为**仅本次内存会话有效**的临时收藏，可在会话内添加或取消（页面刷新或进程冷启动后清空），无需登录即可使用，并展示清晰的会话持久性说明，不谎称云端持久化或跨设备同步。

## 备选方案与权衡

1. **继续保留微信小程序并与 Android 并行三端维护**：
   - 放弃原因：微信小程序强依赖微信主体资质、类目审核、严格业务域名配置、`web-view` 限制与两套条件编译 UI/API 差异，会持续拖慢比赛平台上线与可用端交付；在个人维护与首期聚焦比赛发现/学校唯一登录的前提下，先交付 H5 + Android 签名 APK 更具确定性。
   - 若未来恢复微信小程序，需基于届时项目状态另开 ADR 并重新补齐主体、域名与真机验收，不重开已关闭历史单票。
2. **等待学校官方统一身份认证（OAuth/CAS）接入**：
   - 放弃原因：外部官方审批周期与可达性不受项目控制，将导致用户端登录无限期阻塞；继续复用已核验过的 `@hehuoda/sicau-connectors/auth` 网页认证路线，同时严格限定短时内存处理密码、逐字比对姓名学号、明示告知说明与限流保护，是当前可行且边界清晰的权衡。
3. **H5 将 Refresh Token 存放在 `localStorage` 或 `uni.setStorageSync`**：
   - 放弃原因：浏览器端脚本可读的持久化存储容易在 XSS 场景下导致 30 天长效刷新凭据外泄；采用 `HttpOnly` Cookie + `Origin` + `X-Refresh-CSRF` 可将长效刷新凭据完全隔离在浏览器脚本之外，代价是服务端需额外实现防跨站头校验与多标签并发刷新协调。
4. **直接删掉「找队友」Tab 或保留完整演示组队交互**：
   - 放弃原因：删改三栏结构会连带破坏 ADR 0005 的导航注册契约与回归用例；而保留完整演示交互会让真实线上访客误以为组队已可用。采用方案 B 保留骨架并展示温和暂缓提示，切换成本最低且语义诚实。

## 后果与实施边界

- **实施顺序**：#213 固化契约后，M1 的比赛闭环与 M2 的认证、Android 工程可按各自依赖推进。#58 外部条件与 #143 部署通道可提前准备。M3 的准入、切流与 APK 分发以及 M4 的旧端退役，采用对应 Issue 的前置依赖和验收记录。
- **不以历史构建代替目标端验证**：静态 lint/typecheck/build 与 API e2e 测试不证明 H5 手机浏览器（320/375/390/430px）或 Android 真机（云/离线打包 APK、Keystore、返回键、安全区、系统浏览器外链）通过；各端分别按各自验收矩阵留证。
- **数据库迁移兼容性**：既有 `0004_auth.sql` 中的 `wechat_identities` 等历史表在微信登录下线（#223）时**不执行破坏性删表迁移**，保持对已部署库结构与回滚窗口的兼容，通过关闭开关、移除路由与清理应用引用完成下线。
- **旧 Web 退役前提**：`apps/web` 继续在仓库中保留作视觉/规则对照与应急回滚参考，仅在 M1–M3 H5/Android 稳定且确认无旧源码依赖后按 #90 评估移除。
