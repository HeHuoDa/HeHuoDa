# ADR-0008：管理员独立 Cookie 会话与事务审计

- 状态：采纳，由 #37 实施；前端接线与生产激活分别验收。
- 日期：2026-10-27

## 背景

学生已有微信 Bearer 会话（ADR-0006），管理后台需要受控账号、浏览器刷新恢复和跨模块操作审计。此前公开采集 CLI 的 reviewer 是维护者填写的来源标识，不足以成为 HTTP 身份。复用学生账号并暗中附加管理员权限会混淆两种凭据生命周期；仅在业务提交后追加日志又不能保证发布等操作可追溯。

## 决策

管理员账号、会话和操作分别存入独立的 admin_accounts/admin_sessions/admin_operations。仅允许受控交互命令初始化账号；首版所有有效管理账号均为固定管理员角色，不提供公开注册或动态授权。密码用 Node 内置异步 scrypt 与随机盐，参数见管理认证文档。

桌面管理 Web 使用 HttpOnly、生产 Secure、SameSite=Lax、限定 Path 且无 Domain 的不透明 Cookie，默认绝对12小时，数据库仅存摘要。写接口精确校验 Origin 和会话绑定 CSRF；登录也检查 Origin。停用和密码变更撤销全部旧会话，重新启用不恢复旧权限。学生 Bearer 不能交换或推定管理员身份。

默认保护整个管理路由空间，业务成功与成功审计用同一 PoolClient 原子提交，身份由服务器认证上下文提供。失败尝试另记 failure，CLI 维护者与登录管理员分属不同 actorType。原始凭据及任意请求载荷不进入审计。

## 权衡与后果

相比统一复用学生 Bearer，这一选择增加独立迁移和会话验证代码，但让浏览器管理凭据与小程序学生凭据相互隔离；普通网页脚本不能读取 Cookie。Cookie 会自动随请求发送，因此必须同时维护 Origin/CSRF 与严格 CORS，管理页面和 API 应同源或同站。未接线的管理页面不因后端合并而自动可用。

相比独立异步日志，同事务审计使审计存储故障会拒绝业务写入，增加可用性成本；这是避免“写入成功但没有可信成功审计”的明确取舍。后续模块必须接受调用方事务客户端，不能在内部独立提交。学生认证和旧 CLI 日志保持原有契约。

操作说明、配置、查询范围与非破坏性回退见 [管理员认证、权限与审计](../admin-auth.md)。
